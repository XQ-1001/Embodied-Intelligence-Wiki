Viam 是一家美国开源机器人软件平台公司，由 MongoDB 联合创始人兼前 CTO Eliot Horowitz 于 2020 年在纽约创立。公司致力于打造连接 AI、数据与物理世界的通用软件层，为机器人及智能设备提供从原型开发到全球规模部署的全生命周期平台。Viam 采用"开放核心 + 商业云服务"模式，核心组件 viam-server 开源免费，商业收入来自云数据存储、机群管理和企业级白标服务。截至 2025 年 3 月，公司累计融资约 $1.17 亿，估值约 $2.4-2.85 亿（Dealert 估算），客户覆盖海洋制造、体育娱乐、快餐、工业制造、气候科技等多个领域。[1][3]

1.2 创始人及核心团队

Eliot Horowitz（创始人兼 CEO）：1981 年生，布朗大学计算机科学学士。4-5 岁开始编程，2003 年加入 DoubleClick 研发团队，结识了 DoubleClick 联合创始人 Dwight Merriman。2005 年与 Merriman 联合创办电商搜索引擎 ShopWiki 并担任 CTO，2006 年被《BusinessWeek》评为"25 位 25 岁以下最佳创业者"。2007 年联合创办 10gen（后更名为 MongoDB Inc.），亲手编写了 MongoDB 核心数据库代码。MongoDB 于 2017 年在纳斯达克上市（MDB），市值高峰约 $275 亿。Horowitz 在 MongoDB 担任 CTO 长达 13 年，于 2020 年 7 月卸任后创立 Viam。[2]

Eddie Sharkey（全球销售与合作伙伴负责人）：负责 Viam 的全球销售和欧洲扩张策略。[3]

Joyce Lin（开发者关系主管）：负责开发者社区和 SDK 生态建设，曾在 dotJS 2025 发表演讲展示 Viam 的 JavaScript SDK 在浏览器中编排机器人的能力。[5]

创始人能力画像

Eliot Horowitz 的核心能力集中在开源基础设施软件的构建上——从零编写了 MongoDB 的核心数据库引擎，并将其从开源项目发展为上市公司。这种能力与 Viam 的定位高度一致：为机器人行业构建一个类似"数据库之于应用层"的基础软件平台。他不是机器人学出身，但拥有构建大规模开源开发者平台的一手经验，包括如何设计 API、管理模块化生态、平衡开源与商业。[2]

1.4 技术路线

Viam 的技术架构围绕"让软件工程师像构建云服务一样构建机器人"这一核心设计理念展开。[5]

核心技术栈

  • viam-server（RDK，机器人开发套件）：开源核心二进制程序，运行在机器人的板载计算机（通常为 Raspberry Pi 等单板机）上，提供硬件抽象、运动规划（逆运动学、碰撞规避）、计算机视觉、导航和数据采集等内置服务。所有硬件组件（深度相机、机械臂、电机、传感器）通过统一 API 操作，更换硬件只需更新 JSON 配置文件，无需重写应用代码。[5]
  • viam-agent：轻量级守护进程，一条命令即可安装，负责安装和监控 viam-server，管理模块和 ML 模型的 OTA 更新。[5]
  • viam-micro-server：面向资源受限的微控制器（MCU）和低功耗处理器的嵌入式方案，保留核心功能（硬件抽象、云连接），适用于 IoT 设备、可穿戴设备和微型无人机。[5]
  • 通信栈（gRPC + WebRTC）：gRPC 定义 API schema 和消息结构（Protobuf 二进制序列化，支持 HTTP/2、Unix Domain Socket、蓝牙、串口）；WebRTC 提供点对点直连传输（绕过中心服务器，NAT/防火墙自动穿透）。两者配合实现了"初始握手经 gRPC 协商，数据传输经 WebRTC 直连"的高效模型，无需 VPN 或端口转发。[5]
  • 模块化架构与 Viam Registry：每个硬件驱动、算法服务和 ML 模型都是独立模块，通过语义化版本发布到 Viam Registry。Fragments（可复用配置模板）支持定义一次、部署到数百台设备，并支持每台设备级别的覆盖。[5]

AI/ML 集成

  • 支持在 Viam 平台上使用采集的数据训练模型（选择数据、标注、选择架构、启动训练）
  • 支持导入自有模型（TensorFlow、PyTorch、ONNX）并通过 Registry 部署
  • ML 模型服务在设备端本地运行推理，无需云端往返
  • 内置自动标注和边缘过滤以降低带宽与存储成本

开源策略

Viam 采用"开放核心 + 商业云服务"模式。viam-server、所有 SDK（Python、Go、TypeScript、C++、Rust、Flutter）及 Viam Registry 对个人、研究者和教育用途免费开源。商业收入来自云数据存储、机群管理、远程监控和计算资源的使用量计费。企业客户可选择白标认证（自定义品牌）、使用 TypeScript/Flutter SDK 构建面向客户的应用，并集成内置账单和发票系统。[5]

2 分析层

2.1 团队背景与场景匹配度

Eliot Horowitz 的履历与 Viam 的使命高度匹配。他在 MongoDB 的 13 年经历覆盖了从零打造开源基础软件、建立开发者社区、到最终 IPO 上市的完整周期。MongoDB 的成功证明了"让开发者更容易处理数据"这一价值主张的商业可行性，而 Viam 试图将同一逻辑复制到机器人领域——"让软件工程师更容易处理硬件"。

但值得注意的是，Horowitz 的核心经验在数据库和云基础设施领域，而非机器人学。Viam 的策略不是他自己成为机器人专家，而是通过平台抽象降低机器人学门槛，让已有机器人知识的客户和合作伙伴更容易地构建解决方案。团队在机器人学深度上的不足，通过平台降低门槛来弥补——这是一个合理的取舍，但也意味着 Viam 在尖端机器人研发方面不构成差异化竞争力。

2.2 技术路线与场景适配性

Viam 的技术架构有几个显著优势。其一，gRPC + WebRTC 的双协议通信栈解决了机器人远程控制的 NAT 穿透和低延迟等实际问题，这是 ROS/ROS2 生态中较为薄弱的环节。其二，硬件抽象层允许在不修改应用代码的情况下更换硬件，对多品种小批量制造场景尤为有价值。其三，"从原型到机群无需重写代码"的架构设计消除了规模化部署时的常见痛点。

但从具身智能的角度看，Viam 目前的技术栈更接近"智能设备的操作系统"而非"机器人智能大脑"。平台内置的 AI/ML 功能主要是计算机视觉（目标检测、图像分类、语义分割）和设备端推理部署，不具备 VLA（视觉-语言-动作）大模型或端到端模仿学习等前沿具身智能能力。Viam 的市场定位是基础设施层，而非算法层。

2.3 股东/资本结构影响

C 轮引入的欧洲产业资本（法拉利家族、Camozzi 集团等）具有明确的战略导向——不是纯财务投资，而是为 Viam 的欧洲工业市场拓展铺设渠道。这种"产业资本 + 市场拓展"的捆绑模式有助于降低进入欧洲工业市场的壁垒，但也可能将 Viam 的发展方向部分导向这些产业资本自身的需求。

Union Square Ventures 自种子轮持续领投或重注参与，显示其对 Horowitz 和 Viam 长期愿景的高度信任。但累计融资 $1.17 亿而估值仅 ~$2.5-2.85 亿（Dealert 估算），资本效率相对一般。如果该估值和营收估算准确，10-12x 的营收倍数在 SaaS/平台公司中处于中等偏低水平。

2.4 试错与路径调整

Viam 自 2020 年成立以来的核心定位没有发生根本性转变，一直是"通用机器人软件平台"。但其商业化策略有明显的演进：从早期强调开源和开发者社区，到 2024-2025 年推出 SurfaceAI 这一垂直应用作为"平台能力验证"，再到 C 轮融资时明确将欧洲工业市场作为扩张重点。

SurfaceAI 的推出是一个值得关注的信号——它表明 Viam 意识到纯平台模式在商业落地上需要"锚点应用"来证明价值。这与 MongoDB 早期通过自身使用 MongoDB 来验证数据库能力的策略有相似之处。

2.5 竞争定位与取舍

Viam 在机器人软件平台赛道的主要竞争对手包括：Google/Alphabet 旗下的 Intrinsic（工业机器人软件平台，背靠 Google 资源）、ROS/ROS2（开源机器人中间件，学术界和工业界广泛使用但缺乏商业支持层）、以及 Hugging Face LeRobot（开源机器人 AI 平台，更侧重模型和数据侧）。

Viam 的差异化在于：1）从云/Web 开发工具链借鉴的开发者体验设计（远程开发、无需部署步骤、多语言 SDK）；2）gRPC + WebRTC 的通信栈解决了实际工程问题；3）从原型到机群的无缝扩展。但在具身智能大模型这一维度上，Viam 不如 Physical Intelligence、Skild AI 等专注于"机器人大脑"的公司，也缺乏 Google 的资源体量来同时推进基础模型研发。

Viam 的取舍是明确的：不做最聪明的大脑，做最顺手的工具链。这个定位在短期内可避开与资金雄厚的 AI 模型公司的正面竞争，但长期来看，如果具身智能行业的价值高度集中在模型层而非工具链层，Viam 可能面临被上下夹击的风险。

2.6 其他重要观察

硬件抽象的价值窗口：Viam 的核心价值主张——"更换硬件不重写代码"——在硬件市场高度碎片化的当下有真实需求。但随着机器人行业走向标准化（如英伟达推动的统一计算平台），硬件接口可能会自然收敛，这将在一定程度上削弱 Viam 硬件抽象层的独特价值。

营收规模与估值的匹配度：如果 Dealert 估算的 $2,300-2,500 万年营收准确，那么 Viam 的营收规模仍然较小，对于一家已成立 6 年、累计融资 $1.17 亿的公司来说，商业化速度不算快。不过作为平台型公司，其早期阶段更关注生态建设而非营收增长，这在开源基础设施公司中并非异常（MongoDB 自身也经历了漫长的商业化爬坡期）。

欧洲战略的合理性：意大利拥有强大的中小型制造业基础（"第三意大利"产业区模式），这些企业有自动化升级需求但缺乏自主研发能力，是 Viam 平台的理想目标市场。法拉利家族等产业资本的引入，可能为 Viam 打开意大利高端制造业的大门。
